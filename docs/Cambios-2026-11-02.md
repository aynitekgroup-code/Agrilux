### 2.1 Nuevo archivo SQL: `scripts/agrotrack-geocercas.sql`

Define la tabla `agrotrack_geocercas` en Supabase con las siguientes características:

| Elemento | Detalle |
|----------|---------|
| **Tabla** | `public.agrotrack_geocercas` |
| **PK** | `id UUID` (gen_random_uuid) |
| **FK** | `empresa_id UUID REFERENCES public.empresas(id) ON DELETE CASCADE` |
| **Unicidad** | `UNIQUE (empresa_id, source_key)` — evita duplicados por empresa |
| **Geometría** | `geometria JSONB NOT NULL` con CHECK que valide tipo `Polygon` o `MultiPolygon` y coordenadas en array |
| **Campos fuente** | `source_key TEXT`, `nombre`, `division`, `anexo`, `distrito`, `provincia`, `area_declarada NUMERIC`, `atributos_fuente JSONB` |
| **Auditoría** | `creado_por UUID REFERENCES auth.users(id)`, `created_at`, `updated_at`, `activa BOOLEAN` |
| **Índice** | `idx_agrotrack_geocercas_empresa (empresa_id, division, nombre)` |

#### Función de autorización

- `public.agrotrack_puede_editar_geocercas(p_empresa_id UUID)` → BOOLEAN  
  Retorna true si el usuario autenticado (`auth.uid()`) es miembro activo (`activo = true`) de la empresa con rol `administrador` o `ingeniero`.

#### Políticas RLS (Row Level Security)

| Política | Operación | Condición | Quién puede |
|----------|-----------|-----------|-------------|
| `agrotrack_geocercas_select_member` | SELECT | `public.onboarding_es_miembro(empresa_id)` | Miembros activos de la empresa |
| `agrotrack_geocercas_insert_engineer` | INSERT | `public.agrotrack_puede_editar_geocercas(empresa_id)` | Administradores e ingenieros |
| `agrotrack_geocercas_update_engineer` | UPDATE | `public.agrotrack_puede_editar_geocercas(empresa_id)` | Administradores e ingenieros |
| `agrotrack_geocercas_delete_admin` | DELETE | `public.onboarding_es_admin(empresa_id)` | Solo administradores |

#### Requisito de despliegue

Este archivo SQL debe ejecutarse en el SQL Editor de Supabase **después** de las migraciones de empresas y RLS (onboarding 2.5 y 2.6), ya que depende de `empresas`, `empresa_miembros`, y de las funciones `onboarding_es_miembro` / `onboarding_es_admin`.

### 2.2 Nuevo servicio: `src/lib/agrotrackGeocercas.js`

Módulo de 172 líneas que encapsula toda la lógica de importación y listado de geocercas.

#### Dependencias
- `shpjs` — lectura de archivos ZIP con capas Shapefile
- `supabase` — cliente de Supabase

#### Funciones exportadas

**`listarGeocercas(empresaId)`**
- Consulta `agrotrack_geocercas` filtrando por `empresa_id` y `activa = true`
- Ordena por `division` y `nombre`
- Devuelve `id, empresa_id, nombre, division, anexo, distrito, provincia, geometria, activa`
- Lanza error descriptivo si la tabla no existe (código `42P01`)

**`importarGeocercasZip(file, empresaId, userId)`**
1. Valida que existan archivo, empresa y usuario
2. Parsea el ZIP con `shp()` de shpjs
3. Filtra capas `FeatureCollection`
4. Busca una capa llamada `linderos` con exactamente **129 polígonos**; si no, acepta cualquier capa con exactamente 129 features
5. Valida que cada feature tenga nombre, geometría válida (`Polygon`/`MultiPolygon` con coordenadas en rango WGS84), y que no haya `source_key` duplicadas
6. Genera `source_key` normalizada a partir de `division|anexo|nombre` (sin tildes, minúsculas, guiones)
7. Inserta por lotes de 25 filas con `upsert` (conflicto en `empresa_id, source_key`) — idempotente, se puede repetir sin duplicar
8. Retorna el número de filas guardadas

#### Constantes internas
- `GEOCERCAS_TABLE = 'agrotrack_geocercas'`
- `EXPECTED_FEATURE_COUNT = 129`
- `IMPORT_BATCH_SIZE = 25`

## 6. Modelo de datos — Tabla `agrotrack_geocercas`

```sql
CREATE TABLE IF NOT EXISTS public.agrotrack_geocercas (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  empresa_id UUID NOT NULL REFERENCES public.empresas(id) ON DELETE CASCADE,
  source_key TEXT NOT NULL CHECK (btrim(source_key) <> ''),
  nombre TEXT NOT NULL CHECK (btrim(nombre) <> ''),
  division TEXT,
  anexo TEXT,
  distrito TEXT,
  provincia TEXT,
  area_declarada NUMERIC,
  geometria JSONB NOT NULL CHECK (GeoJSON Polygon/MultiPolygon válido),
  atributos_fuente JSONB NOT NULL DEFAULT '{}'::jsonb,
  activa BOOLEAN NOT NULL DEFAULT TRUE,
  creado_por UUID REFERENCES auth.users(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (empresa_id, source_key)
);
```

### Relaciones

- `empresa_id` → `empresas.id` (cascada de eliminación)
- `creado_por` → `auth.users(id)` (set null al eliminar usuario)
- No hay relación directa con `lotes` ni `fundos` en esta versión (las geocercas pertenecen a una empresa, no a un lote específico)

## 9. Notas sobre aislamiento por empresa

- Todas las geocercas tienen `empresa_id` y RLS restringe la lectura a miembros activos de esa empresa
- La importación y edición están restringidas a roles `administrador` e `ingeniero`
- La eliminación está restringida a `administrador`
- El `source_key` es único por empresa, permitiendo reimportar el mismo ZIP sin duplicar
