## 6. Verificación de Supabase en proyecto (sin tocar producción directamente)

**Archivos:** `scripts/verificar-supabase.sql`

Motivo: el repo pasa de depender del estado actual de Supabase a tener un script de **solo lectura** que informa, antes y después de los `agrotrack-*.sql`, qué tablas, vistas, funciones e índices están presentes (`ok`) o `FALTA`. No modifica filas, no borra objetos, no recrea políticas.

**Uso:**
```sql
-- En Supabase SQL Editor, pega y ejecuta el contenido completo de
-- scripts/verificar-supabase.sql (es UNA sola consulta con CTEs).
-- Cada fila indica tipo/tabla/vista/funcion/indice, su nombre y
-- estado = 'ok' o 'FALTA'.
-- Ejemplo:
--   tabla | agrotrack_posiciones | ok
--   funcion | agrotrack_actividad_flota | FALTA
```

**Qué reporta:**
- Tablas: `agrotrack_posiciones`, `agrotrack_geocercas`, `agrotrack_grupos_unidades`, `agrotrack_flota_unidades`, `agrotrack_visitas_dia`, `agrotrack_visitas_dia_estado`, `agrotrack_vehiculos`, `agrotrack_geocercas_subdiv`, `agrotrack_estado_vivo`, `agrotrack_zonar_latidos`.
- Vista: `agrotrack_geocercas_reportes`.
- Funciones: ubicadas por nombre base (`agrotrack_periodo_flota`, `agrotrack_actividad_flota`, `agrotrack_estado_unidades_flota`, `agrotrack_estado_vivo_flota`, `agrotrack_visitas_geocerca_calc`, etc.).
- Índices GIST/fecha solicitados por el frontend.

Este script no confirma permisos RLS ni contenido (no lee filas), sólo existencia de objetos y de índices. Si alguna fila devuelve `FALTA`, ejecuta los scripts en el orden indicado en la verificación para la flota:
`agrotrack-posiciones.sql → agrotrack-geocercas.sql → agrotrack-visitas-diarias.sql →`
`agrotrack-geometria-reportes.sql → agrotrack-geocercas-reportes.sql →`
`agrotrack-flota-unidades.sql → agrotrack-reportes-flota.sql →`
`agrotrack-posiciones-resumen.sql → agrotrack-rendimiento.sql → agrotrack-tiempo-real.sql →`
`agrotrack-vehiculos-area.sql`.

## 7. Geometría indexada para geocercas (OBLIGATORIO ejecutar antes de validar producción)

**Archivos:** `scripts/agrotrack-geometria-reportes.sql`, `scripts/agrotrack-geocercas-reportes.sql`, `scripts/agrotrack-visitas-diarias.sql`.

Motivo: el cálculo de visitas (`agrotrack_visitas_geocerca_calc`) usaba `ST_MakePoint` no indexado; las 3 unidades `BPI-733`, `BVN-736` y `BVO-945` superaban el `statement_timeout` de 8 s en “Tabla diaria de geocercas” y devolvían HTTP 500 para el usuario.

Archivos entregados:
- `scripts/agrotrack-geometria-reportes.sql` (nuevo, hoy):
  - `agrotrack_posiciones.geom` — punto generado desde `longitud`/`latitud` + índice GIST (`agrotrack_posiciones_geom_gix`).
  - `agrotrack_geocercas_subdiv` — polígonos subdivididos con GIST; `agrotrack_refrescar_geocercas_subdiv()` para repoblarlo tras crear/editar geocercas.
  - `agrotrack_geocercas_reportes` (vista) y política RLS por nombre para el subvista/funciones.
- `scripts/agrotrack-geocercas-reportes.sql` (reescrito, hoy): usa `ST_Contains(s.geom, p.geom)` indexado (`geom`), dejando de reconstruir `ST_MakePoint` en línea.

**Estado de ejecución: en desarrollo en el repo; en PRODUCCIÓN no se aplicó.**

- Esto es responsabilidad del dueño de la base: abrir el SQL Editor de Supabase.
- ORDEN DE EJECUCIÓN:
  1) `scripts/agrotrack-geometria-reportes.sql` — devuelve `fragmentos`, `geocercas`, `posiciones_con_punto` (deben ser > 0).
  2) `scripts/agrotrack-geocercas-reportes.sql` — recrea las funciones con la versión indexada.
  3) `scripts/agrotrack-flota-unidades.sql` — rehace `agrotrack_estado_unidades_flota` (lista maestra de 44 y últimos estados rápidos).
  4) Volver a abrir “Gestión → Reportes” y verificar `BPI-733`, `BVN-736`, `BVO-945`.

**Criterio de aceptación** (runbook mínimo):
```sql
-- 1) Confirmado el uso del índice:
select pg_get_functiondef('public.agrotrack_visitas_geocerca_calc(uuid,timestamptz,timestamptz,text,text)'::regprocedure) ilike '%ST_Contains(s.geom%';
-- 2) Contadores en orden:
select count(*) as fragmentos, count(distinct geocerca_id) as geocercas, (select count(*) from public.agrotrack_posiciones where geom is not null) as posiciones_con_punto
from public.agrotrack_geocercas_subdiv;
-- 3) Medición del caso BPI-733 (Día completo): debe bajar del tiempo original
--    (≈19 s en SQL Editor) a < 1 s y nunca > 8 s:
explain (analyze, buffers)
select public.agrotrack_visitas_geocerca_calc(
  '9ab3a922-1f29-4f06-be93-d6bd7f2457d1',
  '2026-11-17 00:00:00-05:00'::timestamptz,
  '2026-11-17 23:59:59-05:00'::timestamptz,
  'BPI-733', null

```

Dependencias / riesgos:
- Es el compromiso para que “Tabla diaria de geocercas” no devuelva 500 en producción (las 3 unidades con más puntos/pueden disparar HTTP 500).
- Requiere rol con permisos para `CREATE TABLE/INDEX/VIEW/FUNCTION` (rol `postgres`).
- `agrotrack_geocercas_subdiv` es una copia precalculada: tras importar/editar geocercas hay que refrescarla ejecutando `select public.agrotrack_refrescar_geocercas_subdiv();` o automatizarlo con trigger.

## 8. Buscador de máquinas por voz (pedido del cliente)

**Commit:** `50a8085` (`microfono bsucador de placas`).

**Archivos:** `src/components/gestion/fleet/FleetMap.jsx`, `scripts/agrotrack-diagnostico-lotes.sql` (nuevo), `scripts/verificar-supabase.sql` (nuevo), `scripts/agrotrack-geocercas-reportes.sql` (nota de dependencia), `scripts/agrotrack-visitas-diarias.sql` (nota de dependencia).

  campo “Unidad (placa o descripción)”. Funciona en APK (plugin nativo
  `@capacitor-community/speech-recognition`, idioma `es-PE`, permiso `RECORD_AUDIO`) y en web
  (Web Speech API). Al final del dictado: normaliza la placa, la busca y **vuela
  al marcador exacto de la unidad** (`flyTo` + abre el popup) en vez de solo listar opciones.
- **Lectura del popup por voz** (`speechSynthesis`, `es-PE`, rate 0.9): al abrir el popup (o al
  tocar el botón **Escuchar**) se lee la placa, estado, km/h, dirección, velocidad, conductor,
  último evento, km 24 h, odómetro, **geocerca actual**, horas de motor, tanque y fecha.
- `stripVoiceCommand` también recorta “máquina / placa / unidad / vehículo / camión / tractor”
  del inicio del dictado, para que “lleva a la BPI-733” se interprete como la placa.
- El icono de micrófono respeta el patrón ya usado en `SelectorUbicacion` (nativo) y en la
  búsqueda de geocercas/AsistenteMapa (web), sin añadir dependencias externas.
- Verificación SQL solo-lectura (`scripts/verificar-supabase.sql`): confirma existencia de las
  10 tablas esperadas, 1 vista, 28 funciones y los 7 índices GIST requeridos; no toca filas.
- Diagnóstico “Tiempo en cada lote” (`scripts/agrotrack-diagnostico-lotes.sql`): confirma
  índices GIS, volumen de posiciones por día y `EXPLAIN ANALYZE` de `agrotrack_lotes_flota`
  (usó `Function Scan` con `rows=0` en SQL Editor porque `auth.uid()` es NULL;
  el timeout real ocurre en la web con miembro autenticado).

**Nota importante:** el botón de micrófono ya está en producción con el commit `50a8085`.
En APK requiere `Capacitor` y el plugin nativo instalado (ya está en `node_modules`).
