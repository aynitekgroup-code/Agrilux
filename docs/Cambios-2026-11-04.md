# Fase 2 - Separación de experiencias web y móvil

**Proyecto:** Agrilux (`com.agrilux.app2`)  
**Fecha:** 4 de noviembre de 2026  
**Estado:** Implementación base completada y validada por compilación

## Objetivo de la fase

Separar progresivamente la presentación web y móvil manteniendo una única aplicación
React + Vite, una única autenticación, los mismos servicios, permisos, rutas,
Supabase, PWA, Capacitor y almacenamiento offline.

La separación se realiza en la capa visual. No se duplican consultas, reglas de
negocio ni mecanismos de autenticación.

## Cambios implementados

### 1. Selección centralizada de experiencia

**Archivo:** `src/lib/useExperienceType.js`

- APK Android mediante `Capacitor.isNativePlatform()` -> experiencia móvil.
- PWA instalada mediante `display-mode: standalone` o `fullscreen` -> móvil.
- Navegador con ancho menor a `768px` -> móvil.
- Navegador de escritorio -> web.
- Detección segura cuando `window` o `navigator` no están disponibles.
- Actualización reactiva ante cambio de tamaño, orientación o display mode.
- Debounce de 250 ms para evitar cambios bruscos.
- No utiliza el rol del usuario para decidir la experiencia.

### 2. Layout web independiente

**Archivo:** `src/components/layout/WebLayout.jsx`

- Sidebar lateral de escritorio.
- Header superior con título, ubicación y menú de usuario.
- Navegación para Diagnóstico, Ciclo, Parcela y Gestión.
- Área principal de contenido a ancho completo.
- Integración con `AuthContext`, `OnlineStatus`, `AgentStatus` y modales
  compartidos.
- Accesos conservados para ubicación, descarga, manual, contraseña,
  administración y cierre de sesión.

**Corrección adicional:** se eliminó la limitación global de `430px` en escritorio
para que la experiencia web ocupe toda la pantalla. El límite móvil se mantiene
únicamente para la experiencia móvil.

### 3. Layout móvil independiente

**Archivo:** `src/components/layout/MobileLayout.jsx`

- Mantiene el `Layout.jsx` móvil existente como wrapper compatible.
- Conserva header compacto, navegación inferior, ancho máximo móvil y áreas
  seguras.
- Evita duplicar funcionalidad y reduce el riesgo de regresiones.

### 4. Integración de layouts y rutas

**Archivo:** `src/App.jsx`

- Se añadió `ExperienceLayout`.
- Las rutas protegidas se renderizan dentro del layout correspondiente.
- Las rutas públicas continúan sin layout.
- Se conservaron `BrowserRouter`, `AuthProvider`, `AgentProvider`,
  `isAprobado`, redirecciones y validaciones actuales.
- No se creó una segunda aplicación ni un segundo cliente Supabase.

### 5. Micrófono y asistente de voz en web

**Archivo:** `src/components/VoiceAssistant.jsx`

- La web utiliza `SpeechRecognition` o `webkitSpeechRecognition`.
- La APK conserva el plugin nativo de Capacitor.
- El botón funciona como interruptor:
  - Primer toque: enciende y comienza a escuchar.
  - Segundo toque: apaga y detiene el reconocimiento.
- Se añadió reconocimiento continuo y reinicio controlado cuando el navegador
  corta una sesión por silencio o límites internos.
- Se evita que el estado de procesamiento bloquee el segundo toque.
- Se corrigió la limpieza de React que cancelaba el reconocimiento al activarse.
- Se muestran errores explícitos para permisos denegados, micrófono ausente o
  servicio no permitido.
- El procesamiento de la pregunta continúa usando `/api/voice-assistant`.

## Componentes compartidos y variantes

| Compartidos | Web | Móvil |
|---|---|---|
| `AuthContext` | `WebLayout.jsx` | `Layout.jsx` mediante `MobileLayout.jsx` |
| `supabase.js` | Sidebar y header | Header compacto y navegación inferior |
| `offlineStorage.js` | Contenido amplio | Tarjetas y ancho móvil |
| `OnlineStatus` | Integrado en layout web | Conservado en layout móvil |
| `AgentStatus` | Integrado en área principal | Conservado por el layout existente |
| `VoiceAssistant` | Reconocimiento del navegador | Plugin nativo en Capacitor |

Las páginas internas actuales todavía comparten su implementación funcional
dentro de ambos shells. Esto es intencional: la Fase 2 establece la arquitectura
de presentación sin crear variantes ficticias o incompletas.

## Telemetría

La implementación progresiva del módulo de telemetría como primer caso de prueba
queda **pendiente**. Todavía no se creó un `fleetService`, ni dashboards web/móvil,
ni endpoints de GPS, porque primero debe confirmarse el modelo de dispositivos
Pomalca y su contrato de datos.
