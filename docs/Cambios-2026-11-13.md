## 6. Nota sobre el origen de datos de Reportes

Con la versión demo de `main`, `ReportesPage` usa `src/mocks/agrotrackData.js` y **no consulta Supabase**.

Para trabajar con datos reales se requiere:

1. Ejecutar los SQL en Supabase, en orden: `agrotrack-geocercas.sql`, `agrotrack-posiciones.sql`, `agrotrack-posiciones-resumen.sql`, `agrotrack-reportes-flota.sql`, `agrotrack-geocercas-reportes.sql`.
2. Tener un usuario miembro de una empresa (empresa activa).
3. Importar el reporte Zonar (ZIP o `.xlsx`) desde **Gestión → Mapas → "Cargar reporte de unidades"** (`PosicionesImport.jsx`), que hace `upsert` en `public.agrotrack_posiciones`.
4. Importar geocercas (ZIP shapefile) si se desean reportes de entradas/salidas por zona.

> La versión de `ReportesPage` de la rama (basada en RPCs `agrotrack_*` de Supabase) queda disponible en el historial de Git por si se decide reactivar el modo de datos reales.

## 8. Incidencias / problemas conocidos

### 8.1 «Geocercas: límite de velocidad» muestra «El cálculo tardó más de los 8 s que Supabase permite»

**Qué se ve:** el reporte no carga; aparece el aviso rojo con el botón Reintentar.

**Por qué pasa:** el reporte de *entradas y salidas* funciona porque usa `LIKE '%entrada%geocerca%' / '%salida%geocerca%'` (texto, consulta barata). El de *límite de velocidad* cruza todas las posiciones con los 129 polígonos con PostGIS (`ST_Contains` + ventanas), mucho más caro. Si en Supabase aún no se ejecutó la versión optimizada de la RPC (sección 2.5 de `scripts/agrotrack-geocercas-reportes.sql`, con el CTE `limite_min`), la consulta supera el límite de 8 s de Supabase y devuelve el error de timeout.

**Evidencia de por qué sí/no carga:**

- Entrada y salidas ✅ → SQL de texto (barato).
- Límite de velocidad ❌ → PostGIS (caro); requiere la RPC optimizada y, preferentemente, `velocidad_max_kmh` configurada en las geocercas.

**Qué se hizo:** se optimizó la RPC (`limite_min`: solo coordina posiciones con evento "Alta velocidad" o por encima del límite mínimo configurado; de ~100 mil filas a unos pocos cientos) y se retiró el desplegable **"Geocercas"** de este reporte (pedido del cliente): la tabla queda con Fecha y hora · Unidad · Evento · Velocidad (km/h) · Dirección · Geocerca, con el filtro **Mostrar** (Grupos/Unidades) funcionando.

**Qué falta:** ejecutar en el SQL Editor de Supabase la versión actualizada de `scripts/agrotrack-geocercas-reportes.sql`. Si aun así da timeout, reducir el rango a día/mes o elegir una geocerca.
